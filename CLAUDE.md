## Project

Finanpy is a personal finance web app built with Django full stack (server-rendered DTL templates + TailwindCSS). `PRD.md` is the source of truth for scope, data model, URL map, design system and the sprint task list (section 13). Mark tasks as `[X]` in the PRD when completed. Do not add features or dependencies outside the PRD scope. `docs/` holds the project documentation (index in `docs/README.md`); keep it in sync when the project changes.

Current state: Sprint 0 is done except the first git commit (0.1.5). Django 6.1.2 skeleton with pt-br/`America/Sao_Paulo` settings, `TEMPLATES['DIRS']` pointing at the empty `templates/` dir, and the apps `users`, `profiles`, `accounts`, `categories` and `transactions` registered by their `AppConfig`. The custom user (`users.User` + `users/managers.py`) exists, `AUTH_USER_MODEL = 'users.User'` is set and `users.0001_initial` plus all contrib migrations are applied to `db.sqlite3`. The other apps have no models or migrations yet, and there are no views, URLs or templates. The only route is `admin/`.

## Commands

The virtual environment is `.venv` (Python 3.14). On Windows, activate it with `.venv\Scripts\activate`.

```bash
pip install -r requirements.txt
python manage.py runserver
python manage.py makemigrations <app>
python manage.py migrate
python manage.py test                                   # all tests
python manage.py test accounts                          # one app
python manage.py test accounts.tests.SomeTest.test_x    # single test
```

`requirements.txt` is UTF-16 encoded because it was generated by `pip freeze >` in PowerShell. No linter is installed yet; the PRD plans `ruff check`/`flake8` for the PEP 8 review.

## Critical ordering

The custom user model (`users.User`, login by email, `username = None`, manager in `users/managers.py`) and `AUTH_USER_MODEL = 'users.User'` must exist **before the first `migrate`**. `db.sqlite3` already exists, so check whether it holds applied migrations (`python manage.py showmigrations`). If it does, the database must be reset before the custom user is introduced.

## Architecture (planned in PRD section 8)

- **`core`** holds settings, root URLs, `HomeView`/`DashboardView` (`core/views.py`), `UserQuerySetMixin` (`core/views.py`) and `StyledFormMixin` (`core/forms.py`). Each app has its own `urls.py`, which is included in `core/urls.py` with flat URL names (`account_list`, `account_create`, `account_update`, `account_delete`; the same pattern applies to `category_*` and `transaction_*`).
- **Data isolation:** every user-data view uses `LoginRequiredMixin` + `UserQuerySetMixin` (`get_queryset()` filtered by `request.user`). Create views set `form.instance.user`. Forms that select related objects receive `user` via `get_form_kwargs()` and filter their querysets by it.
- **Data rules:**
  - `Account.balance` is a computed property (`initial_balance` + income − expenses via `aggregate(Sum)`). It is never a stored field and is never updated by signals.
  - `Transaction.amount` is always positive; `transaction_type` gives the sign. `Transaction.account` uses `CASCADE`. `Transaction.category` uses `PROTECT`, so the category delete view catches `ProtectedError`.
  - The transaction type must match the category type (validated in `TransactionForm.clean()`).
- **Profile:** created by a `post_save` signal in `profiles/signals.py`, which is imported in `ProfilesConfig.ready()`.
- **Templates:** these live in a root `templates/` dir (requires `TEMPLATES['DIRS'] = [BASE_DIR / 'templates']`). `base.html` defines all component classes once, via `@apply` in `<style type="text/tailwindcss">`. `base_app.html` is the authenticated layout. Partials go in `templates/components/`. Tailwind comes from the CDN `@tailwindcss/browser@4`.

## Conventions

- PEP 8 and **single quotes** in Python.
- Code (names, models, URLs) is in English. All user-facing text (labels, messages, `verbose_name`) is in Brazilian Portuguese.
- Prefer Class Based Views and native Django features.
- Every model has `created_at = DateTimeField(auto_now_add=True)` and `updated_at = DateTimeField(auto_now=True)`.
- Money uses `DecimalField(max_digits=12, decimal_places=2)`, never `float`.
- Create/update/delete actions show success messages (messages framework). Deletes go through a confirmation page.
- UI follows the design system in PRD section 9 / `docs/design-system.md`: dark theme, at most one `btn-primary` per screen, income in emerald, expenses in rose.
- Docker and automated tests come only in the final sprints (9 and 10).

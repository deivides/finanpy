## Project

Finanpy is a personal finance web app built with Django full stack (server-rendered DTL templates + TailwindCSS). `PRD.md` is the source of truth for scope, data model, URL map, design system and the sprint task list (section 13). Mark tasks as `[X]` in the PRD when completed. Do not add features or dependencies outside the PRD scope. `docs/` holds the project documentation (index in `docs/README.md`); keep it in sync when the project changes.

Current state: Sprints 0–9 are done (except the first git commit, 0.1.5). The custom user (`users.User`, login by email), `Profile` (auto-created by signal), `Account` (with the computed `balance` property), `Category` and `Transaction` models exist with migrations applied. Public home, sign up/login/logout, profile edit and full CRUD for accounts, categories and transactions are implemented (transaction list with month/type filters, filtered totals and pagination). The dashboard (Sprint 8) shows total balance, month income/expenses/result, the 5 latest transactions and per-account balances; the design system and code review (Sprint 8) are done and `ruff check .` is clean. The sprint task list with checkboxes lives in `TASKS.md`. `USE_THOUSAND_SEPARATOR = True` is set. Automated tests (Sprint 9) live in each app's `tests.py` and in `core/tests.py`, with coverage measured by `coverage` (PRD minimum: 80%). There is no Docker setup yet (Sprint 10).

## Commands

The virtual environment is `.venv` (Python 3.14). On Windows, activate it with `.venv\Scripts\activate`.

```bash
pip install -r requirements.txt
python manage.py runserver
python manage.py makemigrations <app>
python manage.py migrate
python manage.py test                                   # all tests
python manage.py test accounts                          # one app
python manage.py test accounts.tests.SomeTest.test_x    # single test
coverage run manage.py test                             # tests with coverage (dev tool: pip install coverage)
coverage report -m                                      # coverage report with missing lines
ruff check .                                            # PEP 8 lint (dev tool: pip install ruff)
```

`requirements.txt` is UTF-16 encoded because it was generated by `pip freeze >` in PowerShell. Lint with `ruff check .` (config in `ruff.toml`: line length 79, rules E/W/F/I/Q, single quotes; migrations exempt from E501 only). `ruff` and `coverage` are dev tools installed separately (`pip install ruff coverage`) and must not be added to `requirements.txt`. Coverage config is in `.coveragerc` (branch coverage; omits `.venv`, migrations, `manage.py`, `core/asgi.py` and `core/wsgi.py`).

## Critical ordering

The custom user model (`users.User`, login by email, `username = None`, manager in `users/managers.py`) and `AUTH_USER_MODEL = 'users.User'` must exist **before the first `migrate`**. `db.sqlite3` already exists, so check whether it holds applied migrations (`python manage.py showmigrations`). If it does, the database must be reset before the custom user is introduced.

## Architecture (planned in PRD section 8)

- **`core`** holds settings, root URLs, `HomeView`/`DashboardView` (`core/views.py`), `UserQuerySetMixin` and `UserFormKwargsMixin` (`core/views.py`) and `StyledFormMixin` (`core/forms.py`). Each app has its own `urls.py`, which is included in `core/urls.py` with flat URL names (`account_list`, `account_create`, `account_update`, `account_delete`; the same pattern applies to `category_*` and `transaction_*`).
- **Data isolation:** every user-data view uses `LoginRequiredMixin` + `UserQuerySetMixin` (`get_queryset()` filtered by `request.user`). Create views set `form.instance.user`. Forms that need the user receive `user` via `get_form_kwargs()` (`UserFormKwargsMixin`) and filter their querysets by it.
- **Data rules:**
  - `Account.balance` is a computed property (`initial_balance` + income − expenses via `aggregate(Sum)`). It is never a stored field and is never updated by signals.
  - `Transaction.amount` is always positive; `transaction_type` gives the sign. `Transaction.account` uses `CASCADE`. `Transaction.category` uses `RESTRICT` (not `PROTECT`, which would also block deleting a user who has transactions), so the category delete view catches `RestrictedError`.
  - The transaction type must match the category type (validated in `TransactionForm.clean()`).
- **Profile:** created by a `post_save` signal in `profiles/signals.py`, which is imported in `ProfilesConfig.ready()`.
- **Templates:** these live in a root `templates/` dir (requires `TEMPLATES['DIRS'] = [BASE_DIR / 'templates']`). `base.html` defines all component classes once, via `@apply` in `<style type="text/tailwindcss">`. `base_app.html` is the authenticated layout. Partials go in `templates/components/`. Tailwind comes from the CDN `@tailwindcss/browser@4`.

## Conventions

- PEP 8 and **single quotes** in Python.
- Code (names, models, URLs) is in English. All user-facing text (labels, messages, `verbose_name`) is in Brazilian Portuguese.
- Prefer Class Based Views and native Django features.
- Every model has `created_at = DateTimeField(auto_now_add=True)` and `updated_at = DateTimeField(auto_now=True)`.
- Money uses `DecimalField(max_digits=12, decimal_places=2)`, never `float`.
- Create/update/delete actions show success messages (messages framework). Deletes go through a confirmation page.
- UI follows the design system in PRD section 9 / `docs/design-system.md`: dark theme, at most one `btn-primary` per screen, income in emerald, expenses in rose.
- Tests use Django's native test framework (`django.test.TestCase`) in `<app>/tests.py`; do not add other test libraries. Docker comes only in Sprint 10.
